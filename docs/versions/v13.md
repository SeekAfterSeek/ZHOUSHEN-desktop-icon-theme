# v13 · 用户自选截图 → 像素级回查原图

v12 之后，用户从素材库里挑出 20 张截图，指定「这一张给哪个 APP」，要求按截图里
的人物造型重做图标。v13 就是把这批图做实。

## 关键难点：截图的来源反查

用户给的是**从素材照片上放大后截的图**（缩放倍数实测 0.52~3.67 倍）。这意味着：

- 全局感知哈希（dHash）完全失效——裁剪 + 放大后哈希距离 76~101，判定为「不同图」
- 640px 索引的 ORB 特征也大量失败——裁剪区域在低分辨率索引里只剩一两百像素，
  尺度超出 ORB 金字塔范围
- 全库多尺度模板匹配太慢：4367 张 × 9 个尺度，单张截图要跑数分钟

### 最终解法：人脸锚点 + 精确缩放

1. **人脸作锚点**：同一张脸在截图里高 `fh_s` 像素，在原图里高 `fh_o` 像素，
   则截图是原图的 `fh_o / fh_s` 倍缩放。用 YuNet 检测两边的人脸即可算出精确比例。
2. **按比例还原后做一次模板匹配**：真匹配会逐像素重合，相关值 0.85~0.99；
   假匹配极少超过 0.6。

结果：**20 张截图全部命中**，相关值 0.82~0.99。

## 形态

- **联想电脑管家**：盾牌异形。轮廓**直接取自它原始图标的 alpha 通道**，
  再轻微腐蚀让外发光有一圈，形状与原图标完全吻合。
- **QQ音乐**：圆形 + 金边（沿用 v2 以来的特征）。照片用 P6 的构图——
  黄背景、黑衣、高举蓝色麦克风——切脸高 30% 以保住举起的手臂。
- 其余为圆角方形。

## 部署后必须做的事：强制刷新图标缓存

Windows 对 `.lnk` 的图标按「路径 + 时间戳」缓存。**只替换 ICO 内容、不改时间戳，
桌面会继续显示旧图**——这是「文件明明都对了，桌面却没变」的原因。

```
触碰 ICO 与 .lnk 的修改时间
→ SHChangeNotify(SHCNE_UPDATEITEM) 逐个通知
→ SHChangeNotify(SHCNE_ASSOCCHANGED) 全局重建
→ 删除 iconcache_*.db / thumbcache_*.db
→ 重启 explorer.exe
```

验证改用 Windows shell 的 `SHGetImageList(SHIL_JUMBO)` 取真实渲染的 256px 图标，
逐像素对比母版。9 个图标中心区差异全部 ≤0.2。
